AI machine coding Assignment

1. Problem Statement
Design and build a Contextual Retrieval-Augmented Generation (RAG) pipeline that can ingest a
8-10 page research paper PDF (containing text and tables), extract ground truth QA pairs, index
document chunks using both contextual embeddings and traditional IR methods, and serve
end-to-end query answers via an API.

2. Programming Languages
•

Candidates may choose Python, Java, or TypeScript for implementation.

3. Key Considerations
1. Design Quality: Implement the solution as described below, showcasing your
architectural and coding skills.
2. Modularity & OOP: Write clean, modular code following object-oriented paradigms
and dependency injection.
3. Demo-Ready: The application will be demoed live; ensure it can be run easily.
4. High-Level Design Diagram: Include a system overview diagram (embed as an image or
PDF).
5. Documentation: Provide a README detailing installation, execution steps,
configuration, and any important design decisions.
6. Highlight: Make use of Contextual ritrival RAG solution praposed by Anthropic
(https://www.anthropic.com/news/contextual-retrieval)

4. Requirement / Task Overview
1. Ground Truth Extraction
o From the provided PDF, create a JSON file with atleast 10 QA pairs: {question,
answer, page, span_start, span_end}.
2. RAG Pipeline Implementation
o Chunking: Implement at least two strategies
o Embedding & Indexing:
▪ Contextual: Compute embeddings per chunk using an open-source model
(e.g., SentenceTransformers).
▪ IR Baselines: Build BM25 and TF-IDF indices over the same chunks.
▪ Store embeddings in a vector store (use any OSS vector store).
3. Context Retrieval & API
o Implement retrieval logic that returns top-K chunks for a query using both
contextual embeddings and IR baselines.
o Expose a RESTful endpoint with openAPI spec (e.g., POST /query) that
accepts {q: string, k: number} and returns:
▪ answer: Generated by an LLM(Use any free LLM api) using retrieved
context.
sources: List of chunk IDs and retrieval scores for both methods.

4. Benchmarking & Evaluation
o Latency: Measure average query latency for each retrieval method.
o Semantic Similarity: Compute cosine similarity between the LLM-generated
answer embedding and the ground truth answer embedding.
o (Optional) Recall@K: Evaluate retrieval recall at K={1,3,5} against ground truth.

• Source Code: GitHub repo (preferred) or ZIP archive containing all code.
• Ground Truth File: JSON of QA pairs with span annotations.
• Design Diagram: High level System design overview image or PDF.
• README: Installation, configuration, and execution instructions.
• Benchmark Report: Markdown summarizing latency and semantic similarity results.
